## 4. 기존 MD와의 관계

- 원본은 Unity/C#/PC, 1920×1080 기준(설정 변경 가능), 플레이 가능한 Vertical Slice를 제시한다. 첫 적 1종은 사용자 재확인 완료. 맵은 작은 맵 제안을 대체하여 중간 규모·약 5초 접근 목표로 변경한다.
- 원본의 '2D 게임'은 최신 3D 요청과 충돌한다. 최신 요구 기준으로 3D를 기록했으며 원본 수정은 아직 하지 않았다.
- 원본의 HitBox 충돌 즉시 피해 방식은 확률 방어/공격 성공과 조합 방식이 미정이다. 확률만으로 피해를 주거나 충돌만으로 피해를 주는 구현을 임의로 확정하지 않는다.
- 원본의 Title → Stage → Battle → Victory/Defeat → Title 흐름은 초안이다. 스탯 배분 화면 위치, 승리·패배·재시작 조건을 확인한다.
- 기존 코드 원칙: 책임 분리, FSM 기반 적 행동, 불필요한 재작성 방지, public 최소화, Inspector는 SerializeField, 의미 없는 Manager 금지, 주요 코드 주석, 단계별 컴파일 및 연결 확인.

## 5. 사용자 확인 질문

### 1차 답변 — 2026-10-07

1. 새 프로젝트, Unity 6.3 LTS 희망, 중간 맵·약 5초 접근·적 1종.
2. 자유 3인칭 + 마우스 휠 클릭 락온 토글.
3. 플레이어 공격에서만 선택 개입. 선택 이후 내 공격·적 반응을 실시간 애니메이션으로 보여주고 실시간 전투로 복귀. 성공은 적 분리, 실패는 힘겨루기 후 분리, 각각 약 5개 변형. 적의 일반 공격과 회피는 실시간. 짧고 가벼운 템포.
4. 공격 전 플레이어의 공격 방법을 모션으로 보여주며 확률 성공 여부도 함께 표시. 표시 내용과 확정 시점은 아래 재확인.
5. 검이 왼쪽 아래일 때 오른쪽 위 선택: 왼쪽 아래 → 오른쪽 위 베기. 왼쪽 아래 선택: 한 바퀴 돌면서 왼쪽 아래로 공격. '한 바퀴'가 몸 회전인지 검 궤적인지는 재확인.
6. 에셋 없음. 로우폴리 직접 제작. 추후 교체 고려. 코드 구조를 그림으로 HTML에 유지. 해석이 불확실하면 구현하지 말고 작은 그림/설명으로 즉시 확인 요청.

### 2차 답변 — 2026-10-07

- 선택 슬로모션 중 피격 없음. 공격 실패는 양측 스탯에 따른 적 패링/방어 등으로 발생 가능. 이를 연출 중 무적이나 실패 반격 피해 없음까지 확대 해석하지 않는다.
- 성공률 %와 공격 방향 글자를 표시하고 제한시간 안에 고른다. 추첨 과정은 사용자에게 보여주지 않고 결과를 연출한다. 기존 모션 예고를 글자로 대체하는지 병행하는지는 미정.
- 같은 방향 베기의 회전은 몸 전체 회전으로 확정.
- 속도 원문: '3일때 ... 2회 추가', '2이하는 공격 1번 + 추가 공격 1번', '1이하는 공격 1회', '0 이하는 공격 성공 확률 하락'. 범위가 겹치므로 아래 상호 배타적 해석을 확인한다.
- 좌클릭 진입 → 플레이어·검 포커스 → 마우스 방향 선택 → 좌클릭 확정 즉시 시작. 같은 방향 추가 1회 허용, 이미 추가 선택한 경우 다른 방향으로 마우스를 움직여야 함. 실제 검을 휘두르는 입력 감각 지향.
- 시작점에서 약 1초 좁은 직선 길을 지나 원형 맵에 들어오는 순간 전투 시작. 중앙 적까지 약 5초 보행 배치. 이동속도가 정해져야 미터 단위 크기를 산정할 수 있다.
- 적 돌진/도약 이후 바로 접근하는 플레이어에 대응하는 행동을 요청받음. 회피 주체는 아래 확인.

### 3차 답변 — 2026-10-07

- 아래 속도별 총 타수 표를 사용자가 확인함.
- 연속타도 각 공격을 좌클릭으로 확정. 방향 변경만으로 발동하지 않음. 같은 방향 클릭 3연속 불가, 같은 방향 클릭 2회 후 다른 방향으로 이동하고 클릭하는 것은 가능.
- 선택 시간은 '대략 2초 안에 선택해야 한다고 하면'이라는 예시를 제시함. 잠정 목표로 기록하되 정확한 값, 전체 콤보/타격별 적용, 시간 초과 처리는 미확정.
- 적은 돌진하며 휘두르기(설정 거리 안), 원거리 공격하며 뒤로 회피하기를 모두 갖는다. 무작위 선택이나 거리 밖이면 무조건 후퇴 등의 규칙을 임의로 추가하지 않는다.

### 4차 답변 — 2026-10-07

- 제한시간은 각 타격별이 아니라 콤보 전체에 적용한다. 속도 0=1초, 1=1.3초, 2=1.5초, 3=2초. 이전의 '약 2초' 잠정값을 대체한다.
- 시간 초과 시 남은 공격 취소. 속도 0·1은 역으로 적에게 공격당하며, 속도 2·3은 남은 공격만 취소한다.
- 시간 초과 피격은 선택 중 일반 피격 없음 규칙과 구분되는 명시적 예외이다. 공격 실패(패링/방어)의 피해 규칙과 혼동하지 않는다.
- 시간 초과 반격 피해량·모션·방어/회피 가능 여부는 미정. 이미 완료된 공격을 무효화한다는 뜻으로 해석하지 않는다.

### 확정된 속도·콤보 시간·초과 처리

| 속도 | 총 공격 횟수 | 콤보 전체 제한시간 | 시간 초과 |
|---|---|---|---|
| 0 | 1회 + 성공률 감소 | 1초 | 남은 공격 취소 + 적에게 피격 |
| 1 | 1회 | 1.3초 | 남은 공격 취소 + 적에게 피격 |
| 2 | 2회 | 1.5초 | 남은 공격만 취소 |
| 3 | 3회 | 2초 | 남은 공격만 취소 |

속도 0 성공률 감소량은 미정이다. 제한시간을 후속타마다 초기화하지 않는다.
입력 예: ↗ 클릭 → ↗ 클릭 → ↘로 이동 후 클릭은 가능. ↗ 클릭 → ↗ 클릭 → ↗ 클릭은 불가. 유효한 확정 공격 방향을 비교하며 잘못된 클릭의 비용/타수 소모는 미정.

### 최신 수정 — 사전 예약 방식 (이전 A 선택 철회)

- 사용자는 직전 A(연출 중 타이머 진행 및 다음 공격 입력)를 철회했다. 최신 지시를 우선하며 A 방식으로 구현하지 않는다.
- 속도 0·1: 공격 방향 1개를 확정하면 공격 연출 시작. 기존 1초/1.3초 선택 제한과 초과 피격 규칙은 유지한다.
- 속도 2·3: 검을 휘두르기 전 카메라 포커스/슬로모션 선택 단계에서 각각 2타/3타의 방향을 미리 모두 정한 뒤 공격 연출 시작. 예약은 각 방향을 좌클릭으로 확정한다.
- 1.5초/2초는 전체 콤보 예약 선택에 적용한다. 공격 연출 중 다음 공격을 입력하는 구조는 폐기한다. 카메라 포커스 전환 중 타이머 시작 여부는 미정이다.
- 동일 방향 최대 2연속 제한 유지. 같은 방향 반복은 적 방어 확률을 높이지만 성공 시 추가 피해를 준다. 적용 타격은 이후 답변에서 두 번째로 확정; 보정 수치는 미정.
- 기존 기록의 '확정 즉시 시작'은 속도 0·1의 단타 또는 속도 2·3의 마지막 예약 확정에 적용하도록 최신 요구로 대체한다.

### 최신 확정 — 부분 예약과 같은 방향 두 번째 타격

- 속도 3에서 3타 중 2타만 예약하고 시간이 끝나면 예약한 1·2타를 성공/실패 확률에 따라 실행한다. 선택하지 않은 3타는 생략하고, 두 캐릭터가 멀어지며 교환을 종료한다. 전체 콤보를 취소하지 않는다.
- 위 예시에서 예약된 두 타격을 실행한다는 요청을 보존한다. 첫 타 실패 시 둘째 타도 자동 삭제하는 규칙을 추가하지 않는다. 사망 등 예외 중단은 후속 설계 대상이다.
- 같은 방향 보정은 두 번째 타격만 적용한다. 첫 번째 타격은 기본 피해와 기본 확률을 사용한다.
- 두 번째 타격은 기본 피해 + 추가 타격 피해, 기본 판정 확률에 추가 실패 확률을 반영한다. 실패 확률 증가를 성공률 증가로 잘못 구현하지 않는다.
- 기호식: 첫 타 성공 피해 = D기본, 실패 확률 = F기본. 같은 방향 둘째 타 성공 피해 = D기본 + D추가, 실패 확률 = F기본 + F추가. D/F의 실제 수치와 확률 범위 제한은 미정이다. 기본값에는 승인된 스탯·위치·검 자세 평가를 연결할 예정이며 아직 수식은 없다.
- 같은 방향 최대 2연속 제한 유지. 다른 방향 후속타에 동일 방향 보정을 적용하지 않는다.

### 5차 답변 — 스탯 5종 재작성 (2026-10-07, 확인 질문 대기)

사용자 원문 요지를 그대로 기록한다. 아래 '확인 필요'가 해소되기 전에는 구현하지 않는다. 기존 R12(원거리 1·근거리 2, 원거리는 특수기 3)와 R10(Shift 무적 기본 보유)은 이 답변과 충돌하므로 재확인 대상이다.

| 스탯 | 사용자 명시 내용 |
|---|---|
| 체력 | 플레이어 HP. 낮으면 공격 실패(확률) 시 플레이어가 약간 피해. 높으면 공격 실패 시 적에게 약간 피해 + 정면 180° 공격 성공률 약간 상승. 3: 우클릭 가드로 0.3초 무적 패링(대기 15초, 더 좋은 값 제안 요청). 0: 정면 공격 성공률 매우 하락 + 성공 시 플레이어 피해량 감소 |
| 속도 | 이동속도. 후면 공격 성공률에 영향(높을수록 상승). Shift 대쉬 충전: 0 추가 충전 시간, 1 약간 추가, 2 보통, 3 대폭 증가. 기존 속도별 타수·제한시간 표 유지 여부 확인 필요 |
| 기력 | 스킬 충전 시간: 0 훨씬 김, 1 약간 김, 2 보통, 3 대폭 단축. 3: 8방향 선택 중 가운데 작은 영역에서 Space로 비도 투척 특수기. 첫 사용 100% 성공, 성공 시 실패 확률 대폭 증가 후 시간에 따라 감소, 첫 사용 이후 실패 확률 최소 30% |
| 힘 | 피해 증가. 0: 성공 시 매우 낮은 피해, 특수기 피해 감소. 1~2 점진 증가. 3: 10~20% 확률 치명타(추가 모션 약 3개) + 일반 피해에 추가 피해 |
| 특수기 | 0: Shift 대쉬 무적 없음. 1: Shift 회피와 동시에 0.3초 무적. 2: 좌클릭 공격 후 우클릭 → 적을 빠르게 지나치며 베는 강력한 공격(쿨타임). 3: 같은 공격을 좌클릭 3번 → 강하게 도는 카메라·쉐이킹 + 매우 강력한 피해(쿨타임) |

추가 규칙: 좌클릭으로 왼쪽 방향 공격을 했다면 다음 좌클릭 공격 시 왼쪽 방향의 막힘 확률이 증가한다.

확인 필요: 체력 낮음/높음 경계, 속도 후면 문장 방향(원문 '낮을 경우 실패 확률 낮아짐'), 우클릭 가드와 특수기 2 우클릭 충돌, 특수기 3의 '같은 공격 3번'과 같은 방향 3연속 금지 충돌, 특수기 단계 누적 여부, 비도의 타수 소비·사거리, 왼쪽 막힘 증가의 범위·지속. 세부 질문은 사용자에게 제시함.

### 6차 답변 — 스탯 확인 질문 답변 (2026-10-07)

1. 같은 방향 3연속은 특수기 3일 때만 허용(3번째가 특수기 3 마무리). 같은 방향 누적 표시: 1회 노랑, 2회 파랑, 3회 빨강. 특수기 2 이하이거나 쿨타임 중이면 3번째에 '불가' 표시.
2. 체력 3 가드 패링은 실시간 전투에서 적 공격을 막을 때만. 특수기 2(우클릭 지나가며 베기)는 좌클릭 공격에 들어갔을 때만.
3. 특수기 단계는 누적(3은 1·2 효과 포함).
4. R12 수정: 원거리 특수기 = 비도(기력 3), 근거리 2개 = 특수기 2·3.
5. 속도별 타수·제한시간 표 유지.
6. 체력 0~1 = 낮음(실패 시 플레이어 약간 피해), 2~3 = 높음(실패 시 적 약간 피해 + 정면 성공률 상승). 0은 추가 패널티.
7. 속도가 낮을수록 후면 공격 성공률 하락, 높을수록 상승.
8. 정면/후면 = 적이 바라보는 방향 기준 플레이어 위치(정면 180° 반원).
9. 비도: 8방향 가운데 작은 원에 마우스를 두고 좌클릭. 예약 타수를 쓰지 않고 바로 던짐. 사용 후 다음 좌클릭 공격(다음 선택)의 성공률 하락, 다다음에 복귀. 실패 확률 하한 30%(성공 최대 70%).
10. 좌우 묶음(↖←↙ / ↗→↘) 적용, ↑↓ 제외. 다음 콤보 선택에 적용. 다음 콤보에서도 같은 쪽이 성공하면 다다음 콤보에서 실패 확률이 더 오른다.
11. 제안 수치로 우선 시험 구현.

### 7차 답변 — 전투 연결 전 확인 (2026-10-07)

1. 비도를 던지면 현재 선택 단계(슬로모션)가 즉시 종료된다. 검 공격을 이어서 예약하지 않는다.

3. 10포인트를 다 쓰지 않아도 시작할 수 있다. 0포인트 시작은 하드코어 플레이로 허용한다.

### 설계 분리안 (아직 클래스 생성 승인 아님)

기존 PlayerController / PlayerMovement / PlayerCombat / PlayerHealth 구성을 출발점으로 한다. 입력, 이동, 공격 판단, 피해 처리의 책임을 분리한다. 추가로 거리·방향 평가, 확률 계산, 전투 상태 전환, 슬로모션 복구, 스탯 데이터, 파괴 오브젝트의 책임 분리가 필요할 수 있다. 클래스명·구조 확정 전 사용자와 상담한다. 적은 기존 FSM 방침을 따른다.

위 이름은 제안이고 생성된 클래스가 아니다. 책임 분리가 목적이며 사용자가 게임 규칙을 승인해도 이 표의 세부 구현 기술까지 승인했다고 간주하지 않는다.

확정된 큰 흐름: 실시간 전투 → 플레이어 근거리 공격 선택(슬로모션) → 내 공격과 적 반응의 실시간 교환 연출 → 실시간 전투. 적에게 별도의 고정 턴을 부여하는 구조로 구현하지 않는다.

판정 흐름: 입력 → 거리/각도/검 자세 평가 → 카메라 포커스 및 성공률·방향 글자·타이머 → 단타 확정 또는 콤보 전체 예약 완료 → 내부 판정 결과에 맞는 연출 → 실시간 복귀. 내부 추첨의 정확한 타이밍, 연속타 분기와 실패 중단은 미정이다.

검 궤적 두 예시와 몸 전체 회전은 확정. 카메라/캐릭터 기준 좌표, 나머지 자세 조합, 결과별 종료 자세는 미정. 시작 8방향×목표 8방향을 모두 별도 수작업 애니메이션으로 만들겠다고 약속하지 않는다. 로우폴리 제작 방식과 애니메이션 재사용 방식은 후속 설계에서 제시한다.

## 7. 검증 계획

- 스탯 각 0~3, 합계 규칙 및 불법 시작 차단; 힘 0 등 승인된 제약 검증.
- 거리 경계 바로 안/밖의 좌클릭, 전투 구역 밖 행동, 허공 베기 중 접근.
- 8방향 입력과 취소·확정, 연속 공격 후 검 자세, 전후측방 및 고저차 평가.
- 확률 계산은 고정 난수 입력으로 재현 가능하게 검증하고 범위를 벗어나지 않는지 확인.
- 선택 슬로모션 중 피해 차단, 단타 확정 또는 예약 완료/승인된 부분 예약 만료 후 공격 시작, 내부 추첨 미노출, 시간초과 및 사망·재시작·취소 후 시간 정상화.
- 속도별 1/1/2/3타, 같은 방향 3연속 차단, 방향 변경만으로 공격되지 않음 검증. 속도별 전체 제한시간과 초과 시 0·1 피격 / 2·3 취소 분기를 검증. 사전 예약 완료 또는 승인된 부분 예약 만료 경로에서 연출 진입하는지 검증. 예약 미완료·잘못된 클릭·동일 방향 두 번째 타격만 추가 피해·추가 실패 확률 적용을 검증. 보정 수치와 기타 부분 예약 사례는 승인 후 검증.
- 무적 시작/종료 경계, 중복 피격, 광역기 예고 범위와 실제 범위 일치.
- 맵 파괴 후 이동/공격 가능 여부 및 반복 전투 초기화.
- '예정', '작성', '컴파일 확인', '플레이 검증'을 구분하여 보고한다. 실행하지 않은 항목을 완료 처리하지 않는다.
