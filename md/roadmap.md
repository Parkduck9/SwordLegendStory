## S4 적 AI — 설계 1.0 `[확인]` → `[구현]` (2026-10-07 사용자 "진행")

근거 요구: R06(맵 파괴·강한 광역 중심, 방어는 확률), R11(빠른 추적, 원거리 도약 내려찍기, 근거리 큰 검, 중거리 투척), R16(소울라이크보다 가벼운 템포), R20(돌진 휘두르기 + 원거리 공격하며 후퇴, 돌진·도약 직후 붙는 플레이어 대응). 맵 파괴는 S6로 미룬다.

### 1. 상태 흐름

```
대기 ──입구 진입──▶ 추적 ──패턴 선택──▶ 예고 ──▶ 공격 ──▶ 후딜 ──▶ 추적
                     ▲                    │                    │
                     │                    └ 플레이어 공격 성공 → 경직 0.4초 ┘
                     └──────────── 후딜 끝에 3.5m 안이면 '후퇴 사격' ─┘
정지(멈춤): 플레이어 선택·교환 중 / 패링 무방비 중          HP 0 → 사망
```

- **대기:** 입구 트리거 전에는 가만히 있는다.
- **추적:** 플레이어 쪽으로 6m/s 이동(플레이어 보행 5m/s보다 빠르고 대쉬보다 느림). 360°/초로 몸을 돌린다.
- **예고:** 바닥에 붉은 범위 표시와 자세(검 들어올림 등). 예고 마지막 0.2초에 방향·위치를 고정한다(그 전엔 플레이어를 따라감) → 마지막 순간 대쉬로 피할 수 있음.
- **공격:** 판정은 예고에 보여준 범위와 같은 데이터로 한 번만 한다.
- **후딜:** 몸을 돌리지 않는다 → 후딜 중엔 측면·후면을 잡기 쉽다(후면 성공률 보정이 의미를 가짐).

### 2. 공격 패턴

| 패턴 | 선택 조건 | 예고 | 후딜 | 피해 | 범위 |
|---|---|---|---|---|---|
| 큰 검 휘두르기 | 0~3.5m | 0.5초 | 0.6초 | 15 | 정면 부채꼴 반경 3.5m · 140° |
| 돌진 베기 | 3.5~8m | 0.6초 | 0.8초 | 18 | 폭 1.5m · 길이 8m 직선, 끝까지 돌진 |
| 투척 | 8~15m | 0.5초 | 0.5초 | 8 | 투사체 18m/s, 반경 0.4m, 유도 없음 |
| 도약 내려찍기 | 15m 이상 | 0.9초(체공) | 1.0초 | 25 | 착지점 원형 반경 4m |
| 후퇴 사격 | 돌진·도약·휘두르기 후딜 직후 3.5m 안 | 0.4초 | 0.4초 | 8 | 뒤로 4m 도약하며 투사체 1발 |

선택 규칙(무작위 없음, 예측 가능한 템포):

1. 직전 공격이 돌진 베기·도약 내려찍기·큰 검 휘두르기이고, 후딜이 끝났을 때 플레이어가 3.5m 안 → **후퇴 사격**(R20 "붙는 플레이어 대응").
2. 그 외에는 거리 구간으로 선택.
3. 같은 패턴을 3번 연속 쓰지 않는다. 3번째가 되면 인접 구간 패턴으로 바꾼다(예: 휘두르기 3연속 → 돌진 베기).
4. 공격 사이 최소 간격 0.3초(추적 상태 유지).

### 3. 플레이어 시스템과의 연결

| 상황 | 적 동작 |
|---|---|
| 플레이어 선택 화면(포커스·선택)·교환 연출 중 | **정지**. 진행 중이던 예고도 멈춘다. 선택 중 피격 없음 규칙 유지 |

## S5 교환 연출 — 설계 1.0 `[확인]` → `[구현]` (2026-10-07 사용자 "진행")

판정은 지금처럼 교환 전에 모두 끝나 있다. 연출은 결과를 보여주기만 하고 확률을 다시 계산하지 않는다.

### 1. 타격 1회의 시간표

```
준비 0.08초 → 궤적 0.14초 → 접촉(피해 적용 · 히트스톱 0.06초) → 반응 0.25초(다음 타 준비와 겹침)
타격당 약 0.3초 · 3타 + 분리 ≤ 1.5초
```

- 피해는 **접촉 순간 한 번만** 적용(기존 strikeId 원칙).
- 마지막 타 반응이 곧 분리 연출이다(별도 밀어내기 없음).

### 2. 검 자세와 궤적

- 플레이어 검은 8방향 중 하나의 **끝자세**를 가진다. 공격 방향 D를 고르면 궤적은 "현재 끝자세 → D", 끝나면 끝자세 = D.
- 현재 끝자세와 D가 **같으면** 몸 전체를 한 바퀴 돌리며 D로 벤다(R18, 1차 답변 예시).
- 예: 끝자세 ↙ → ↗ 선택 = 왼쪽 아래에서 오른쪽 위로 올려 베기. 끝자세 ↙ → ↙ 선택 = 한 바퀴 돌며 왼쪽 아래 베기.
- **이월 제안:** 끝자세는 콤보 안에서, 그리고 다음 교환까지 유지. 실시간 전투에서 2초 동안 공격하지 않으면 기본 자세(↘)로 돌아간다.
- **선택 화면 표시 제안:** 현재 끝자세 방향에 작은 검 아이콘을 띄워, 같은 방향을 고르면 회전 베기가 된다는 걸 보여준다.
- 검 자세가 성공률에 영향을 주는 규칙(R05 "검 위치")은 **이번 단계에서 만들지 않는다**. 수식이 정해지면 별도 단계로.

## S7 게임 흐름 — 설계 1.0 `[확인]` → `[구현]` (2026-10-07 사용자 "진행")

근거 요구: 원본 MD 흐름(Title → Stage → Battle → Victory/Defeat → Title), R08(시작 시 5스탯 0~3, 총 10), 7차 답변(10포인트 미소진 허용, 0포인트는 하드코어), 기존 미정 항목(스탯 화면 위치, 승패·재시작 조건, 저장 여부, 재배분 허용, 전투 구역 이탈). 화면은 S8 아트 전까지 지금과 같은 임시 IMGUI로 만든다.

### 1. 전체 흐름

```
타이틀 ──시작──▶ 스탯 배분 ──출발──▶ 진입로 → 전투장(입구 닫힘) → 전투
  ▲                 ▲                                            │

선택한 스탯은 장면 사이에서 `RunSetup`(정적 보관)으로 넘긴다. Foundation을 바로 실행하면(에디터 테스트) 지금처럼 PlayerStats Inspector 값을 쓴다.

### 4. 스탯 배분 화면

```

#### 4. 기술 방식

- 모델은 Humanoid 아바타로 가져오고, 애니메이터 컨트롤러는 **에디터 코드로 생성**(손으로 만들지 않아 재생성 가능).
- 검 팔 IK: S8 설계의 Animation Rigging 패키지 대신 **Unity 기본 Humanoid IK**(OnAnimatorIK)를 쓴다 → 추가 패키지 설치 불필요.
- 연출 코드 정리: ExchangeDirector가 "몸통 각도"를 직접 주던 부분을 **"반응 종류 재생"** 같은 의미 있는 호출로 바꾸고, 블록 인형(FighterRig)과 새 캐릭터(AnimatorRig)가 같은 호출을 받게 한다. 모델이 없으면 블록 인형으로 자동 대체.

### R5 검 자세 판정 — 세부 설계 `[확인]` → 구현 중 (2026-10-08 사용자 "이대로 진행, 나중에 바꿀 수 있게")

**바꾸는 방법(나중에):** 수치·매핑은 `StatTuning`의 "Sword stance (R5)" 항목만 고친다. 상성표로 바꿀 때도 같은 자리(`StatEffects.StanceBonus`) 하나만 바뀌므로 화면·판정·연출이 함께 따라간다.

**정정:** 앞서 대화에서 "↗ 다음 ↙는 불리"라고 예를 들었으나 반대다. 현재 연출에서 검은 시작 자세 → 목표 방향 끝으로 움직이므로 ↗→↙는 몸을 가로지르는 가장 큰 베기(유리), ↗→↑는 45°만 꺾는 짧은 베기(불리)다.

#### 1. 각도 수식 — "얼마나 크게 휘두르나"

시작 자세 S에서 목표 D까지 8방향 칸 수 k(0~4).

| k | 각도 | 이름 | 성공률 |
|---|---|---|---|
| 4 | 180° | 크게 베기(반대편으로 가로지름) | **+10%** |
| 3 | 135° | 넓게 베기 | **+5%** |
| 2 | 90° | 보통 | 0 |
| 1 | 45° | 짧게 꺾기 | **−10%** |
| 0 | 0° | 회전 베기(기존 규칙 그대로, 각도 보정 없음) | — |

- 시작 자세: 첫 타는 현재 검 자세, 이후 타는 바로 앞 예약 방향(기존 `SwordStance.Predict`와 같음). 선택 화면 표시와 실제 판정이 같은 값을 쓴다.
- 확정 성공(마무리 3타·패링 반격·지나가며 베기·비도)은 영향 없음. 최종 성공률은 기존 하한·상한 안.
- 수치는 시험값(`StatTuning`에서 조정).

#### 2. 움직임 → 검 자세 — "검은 움직이는 반대쪽으로 끌린다"

실시간 상태에서 0.25초 이상 계속 움직이면, 캐릭터 기준 이동 방향의 반대쪽으로 검 자세가 바뀐다(락온 중 옆걸음·뒷걸음 포함).

| 움직임 | 검 자세 | 크게 베기(+10%)가 되는 공격 |
|---|---|---|
| 앞으로 달리기 | ↓ 낮게 끌기 | ↑ 올려 베기 |
| 뒤로 물러남 | ↑ 머리 위로 | ↓ 내려 베기 |
| 왼쪽 옆걸음 | → 오른쪽에 남김 | ← |
| 오른쪽 옆걸음 | ← | → |
| 대각선 이동 | 대각선 반대(예: 앞+왼 → ↘) | 그 반대 대각 |
| 점프(공중) | ↑ 위로 듦 | ↓·↙·↘ (기존 공중 +10%와 겹침) |
| 대쉬 | 대쉬 방향 반대쪽 | 대쉬 방향 쪽 |
| 멈춤 | 마지막 자세 유지 → 2초 후 ↘ (기존) | — |

- 의도: "들어가는 방향으로 크게 벤다" — 접근 방법이 곧 다음 공격 준비가 된다.
- 화면: 검이 실시간으로 그 자세에 들려 있음(AnimatorRig), 선택 화면 칸마다 크게/짧게 표시.

#### 3. 다른 방법 (비교)

| 순위 | 방법 | 장점 | 단점 | 한줄평 |
|---|---|---|---|---|
| **1** | **움직임에 따라 자동(위 표)** | 추가 키 없음, 움직임이 곧 준비 | 원치 않는 자세가 될 수 있음(검이 보이고 선택 화면에 표시해 보완) | 이동과 공격이 하나로 이어짐 |
| 2 | 별도 키로 자세 고르기(예: 휠 스크롤) | 완전한 통제 | 조작 증가, 실시간 중 손이 바쁨 | 정확하지만 번거로움 |
| 3 | 마지막 공격 끝자세만 사용 | 가장 단순 | 이동이 판정과 무관 | 요청을 반영 못 함 |
