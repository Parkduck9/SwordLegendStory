# 3D 무협 액션 — 구현 설계서

설계 버전 1.0 · 2026-10-07 · 사용자 검토용 · 게임 코드 미작성

## 1. 읽는 순서와 상태

현재 요구사항은 `game-plan.md`, 구현 구조는 이 문서, 시각 설계도는 `../html/design.html`에서 관리한다. 원본 `../Unity 3D 프로젝트.md`는 보존한다. 과거 대화 기록과 현재 사양이 충돌하면 최신 확정 요구와 이 문서의 확정 표를 먼저 확인한다. 기술적 선택은 아래 **설계 제안**으로 구분하며, 게임 규칙 미정값을 임의로 채우지 않는다.

이번 산출물은 설계 문서다. Unity 프로젝트, C# 클래스, 모델, 애니메이션을 생성한 상태가 아니다. Unity 설치·패치 버전·렌더 파이프라인은 아직 확인하지 않았다. 설치나 패키지 추가는 이번 작업 범위가 아니다.

## 2. 확정된 게임 계약

- 새 Unity 프로젝트, Unity 6.3 LTS 희망. PC 3D, 적 1종, 중간 크기 테스트 맵. 시작점에서 좁은 직선 길 약 1초, 원형 전투장 입구에서 중앙 적까지 약 5초 보행 배치. 원형 맵 진입 순간 전투 시작.
- WASD 이동, 마우스 자유 3인칭, 휠 클릭 락온 토글, Shift 짧은 무적 회피. 점프와 특수기 존재, 상세 키·비용은 미정.
- 사거리 밖 좌클릭은 허공 베기. 사거리 안에서는 선택 진입, 카메라가 플레이어·검을 포커스한다. 선택 중 일반 피격 없음.
- 방향 이름과 성공률 %를 표시. 각 방향은 마우스로 선택하고 좌클릭으로 예약. 속도 0·1은 1타 확정 후 실행, 속도 2·3은 전체 예약 후 실행. 연출 중 다음 타를 입력하는 이전 A 방식은 폐기.
- 같은 방향 최대 2연속. 같은 방향 두 번째 타격만 기본 성공 피해에 추가 피해, 기본 실패 확률에 추가 실패 확률을 더한다. 실제 추가량은 미정.
- 속도 3에서 2타 예약 후 만료: 예약된 1·2타 판정·연출, 미선택 3타 생략, 두 캐릭터 분리. 첫 타 실패만으로 예약된 둘째 타를 자동 취소하지 않는다. 사망 같은 예외는 별도 결정.
- 적 공격과 일반 회피는 실시간. 적은 근거리 검 휘두르기, 중거리 투척, 원거리 도약 광역기, 돌진 베기, 원거리 공격을 동반한 후퇴를 가진다. 선택 우선순위는 미정.
- 검 시작이 ↙일 때 ↗ 선택은 올려 베기. ↙ 선택은 몸 전체 회전 후 ↙ 베기. 성공/실패 교환 연출은 각 약 5개 변형을 목표로 한다.
- 체력·기력·속도·힘·특수기에 총 10포인트, 각각 0~3. 스탯별 효과는 game-plan.md 5·6차 답변이 최신이며, 원거리 특수기 = 비도(기력 3), 근거리 = 특수기 2·3이다. 규칙 계층은 `Scripts/Battle/`에 구현됨(implementation-status.md 참조).

| 속도 | 최대 예약 타수 | 전체 선택 시간 | 미선택 상태에서 시간 초과 |
|---|---:|---:|---|
| 0 | 1 | 1초 | 취소 + 적에게 피격, 성공률 감소량 미정 |
| 1 | 1 | 1.3초 | 취소 + 적에게 피격 |
| 2 | 2 | 1.5초 | 남은 공격 취소, 예약분 처리의 일반화는 제안 |
| 3 | 3 | 2초 | 남은 공격 취소, 2타 예약 시 2타 실행 확정 |

## 3. 전체 구조 — 설계 제안

세 층으로 나눈다. **규칙**은 예약 유효성·수치·확률을 계산하고, **진행**은 어떤 상태인지와 언제 실행할지 결정하며, **표현**은 모델·카메라·애니메이션·UI를 출력한다. 표현에서 별도로 명중 주사위를 굴리거나 피해를 중복 적용하지 않는다.

| 모듈 | 주요 책임 | 입력 → 출력 | 담당하지 않는 일 |
|---|---|---|---|
| PlayerController | 상태별 입력 전달 | 이동/클릭/회피 → 명령 | 피해 계산 |
| PlayerMovement | 보행·점프·회피 이동 | 명령·이동 설정 → 위치 | 공격 확률 |
| ThirdPersonCamera | 자유/락온/공격 포커스 전환 | 목표·상태 → 카메라 | 예약 확정 |
| EncounterTrigger | 입구 진입 감지 | 진입 → 전투 시작 요청 | 적 패턴 선택 |
| BattleFlow | 전투 상태 전환의 단일 책임 | 명령·완료 이벤트 → 상태 | 모든 세부 로직 통합 |
| SelectionSession | 남은 시간·입력 허용·예약 세션 | 방향 클릭 → 예약/종료 사유 | 공격 애니메이션 |
| ComboRules | 타수 제한·반복 방향 검증 | 속도·예약 목록·후보 → 허용 여부 | 시간·카메라 |
| CombatEvaluator | 거리·방향·검 자세·스탯 평가 | CombatSnapshot → AttackEstimate | 난수 추첨 |
| CombatResolver | 내부 성공/실패 판정 | 계획·평가값·난수 → 결과 목록 | 화면 연출 |
| ExchangeDirector | 예약 타격과 양측 반응 동기화 | 결과 → 타격/반응/분리 이벤트 | 성공률 재추첨 |
| Health | 피해 적용·사망 | 고유 타격 ID와 피해 → 체력·사망 | UI/애니메이션 |
| EnemyBrain | 적 FSM과 패턴 선택 | 거리·상태 → 공격 요청 | 플레이어 콤보 예약 |
| TimeController | 선택 슬로모션 적용·복구 | 상태 → 게임 시간 제어 | 난이도 판단 |
| CharacterVisual | 모델·검 부착·모션 출력 | 자세/연출 요청 → 시각 표현 | 전투 규칙 |
| CombatHUD | 방향·성공률·예약 슬롯·타이머 | 표시 모델 → UI | 확률 계산 |

통신 제안: BattleFlow가 세션과 연출을 직접 조정하고, 완료·사망처럼 여러 소비자가 필요한 이벤트만 제한적으로 사용한다. 전역 이벤트 버스나 범용 Manager는 만들지 않는다. 모든 클래스에 인터페이스를 붙이지 않고 난수·시간·모델 교체 지점만 경계를 둔다.

## 4. 상태 전환 설계

| 상태 | 진입·실행 | 종료 경로 | 확정/제안 |
|---|---|---|---|
| Exploration | 시작 경로 이동 | 입구 → Realtime | 확정 |
| Realtime | 적 추적·공격, 플레이어 이동·회피 | 공격 범위 밖 → 허공 베기; 안 → Focus | 확정 |
| Focus | 카메라 포커스·슬로모션·피격 보호 | 선택 가능 → Planning | 별도 내부 상태는 제안 |
| Planning | 방향·성공률 표시, 타이머, 예약 목록 | 가득 참 → Resolving; 만료 → 아래 분기 | 사전 예약 확정 |
| Resolving | 확정 계획을 판정 결과로 변환 | Exchange | 판정 시점 제안 |
| Exchange | 타격 순서·적 반응·피해 이벤트 | 예약분 종료 → Separation | 연출 확정, 이벤트 방식 제안 |
| TimeoutReaction | 속도 0·1 시간초과 피격 | 반격·분리 후 Realtime 또는 Defeat | 피격 확정, 상세 미정 |
| Separation | 두 캐릭터 분리·시점 복구 | Realtime | 확정 |
| Victory / Defeat | 입력·세션·시간 정리 | 재시작/타이틀 | 종료 UI·흐름 제안 |

사거리 경계 수치, Focus 중 타이머 시작 여부, 선택 취소는 아직 결정하지 않는다. **제안:** UI가 입력을 받을 수 있을 때 타이머 시작, 슬로모션 영향을 받지 않는 실제 경과시간 사용. 전체 예약을 완료하면 제한시간이 남아도 즉시 연출. 미정 규칙은 구현 전에 사용자 확인.

만료 분기: 속도 0·1 미예약 → TimeoutReaction. 속도 3에서 2개 예약 → 두 타격 실행 후 Separation. **제안:** 속도 2·3의 모든 부분 예약도 예약분만 실행하고, 0개면 공격 없이 복귀. 이 일반화는 아직 승인되지 않았다.

종료 경로는 성공·실패뿐 아니라 사망·재시작·씬 종료도 포함한다. 어떤 경로에서도 선택 보호, 카메라 포커스, 시간 배율, 커서 입력 모드가 남지 않도록 해제 책임을 BattleFlow에 집중한다.

## 5. 데이터 계약 — 이름과 타입은 제안

| 데이터 | 핵심 필드 | 수명 |
|---|---|---|
| CharacterStats | health, stamina, speed, strength, special (0~3) | 캐릭터 생성부터 |
| SpeedRule | speed, maxHits, selectionSeconds, timeoutMode | 설정 데이터 |
| CombatSnapshot | 양측 위치/방향/검 자세/스탯, 거리·각도, 유효 목표 | 선택 평가용 |
| AttackIntent | 순번, 목표 방향, 이전 예약 방향, 반복 여부 | 예약 슬롯 |
| ComboPlan | sessionId, intents, 종료 사유(완료/만료) | 선택 완료부터 교환 종료 |
| AttackEstimate | 성공률, 성공 피해, 반복 보정 표시 | 후보 UI |
| AttackOutcome | strikeId, 성공/방어/패링 분류, 피해, 연출 식별자 | 판정 후 불변 |
| EnemyActionDefinition | 패턴, 거리 조건, 예고/공격/후딜, 광역 형태 | 설정 데이터 |
| ExchangeVariant | 호환 시작/종료 자세, 반응 유형, 타격 시점 | 시각 데이터 |

방어와 패링을 별도 결과로 분류하는 것은 표현상 필요 후보이며, 별도 확률로 추첨할지는 미정. 8방향 좌표 기준도 미정이다. 확률은 내부에서 0~1, UI에서 %를 쓰는 방식을 제안한다. 설정은 편집 가능한 데이터로 분리하고 미승인 수치를 기본값처럼 채우지 않는다.

## 6. 판정과 연출의 일관성

1. 선택 UI의 예상 성공률은 CombatEvaluator가 만든다. UI에서 자체 수식을 복사하지 않는다.
2. 예약 클릭은 목록에 AttackIntent를 추가한다. 예약 도중에는 실제 공격 피해가 발생하지 않는다.
3. 전체 예약 또는 승인된 만료 경로에서 ComboPlan을 확정한다.
4. **제안:** 확정 계획을 내부 판정하고 결과 목록을 연출에 넘긴다. 예약 당시 상태를 고정할지, 예상 검 끝자세를 순차 적용할지는 검 자세 규칙 확정 후 결정한다.
5. 연출의 타격 시점에 strikeId로 피해를 한 번만 적용한다. 검 접촉 시각 효과가 피해를 재적용하지 않는다.
6. 예약분이 끝나면 결과에 맞는 분리 연출을 재생한다. 적 사망 시 분리 대신 종료할지는 확인한다.

반복 예: [↗, ↗, ↘]에서는 둘째 타만 D추가/F추가 적용. [↗, ↘, ↘]에서 마지막 타를 같은 규칙으로 처리하는 일반화는 설계 제안이다. [↗, ↗, ↗]은 세 번째 예약 불가. 잘못된 클릭은 타수를 소비하지 않고 방향 변경 안내만 주는 안을 제안한다.

피해 D2 = D기본 + D추가, 실패 F2 = F기본 + F추가. 확률 상한, 스탯·후방·검 자세 보정의 결합 순서와 값은 미정이다. 확정되지 않은 수치 예제를 실제 밸런스로 넣지 않는다.

## 7. 입력과 UI 설계 제안

- 실시간: WASD, 마우스 시점, 휠 락온, 좌클릭 공격, Shift 회피. 점프/기술 키는 후속 승인.
- 선택: 마우스가 방향 후보를 고르고 클릭이 슬롯을 채운다. 같은 클릭이 실시간 진입과 첫 슬롯 예약을 동시에 처리하지 않도록 상태 전환 입력을 분리한다.
- 화면 구성: 플레이어·검 포커스, 8방향 이름과 성공률, 하단 1~3개 예약 슬롯, 남은 시간, 같은 방향 재사용 시 위험/추가 피해 안내. 정확한 배치는 HTML 와이어프레임 참조.
- 선택 성공률은 아직 계산식이 없으므로 설계도에 임의 숫자를 넣지 않는다. 슬롯은 실제 게임이 아닌 설명용이다.
- 락온 상태로 선택에 진입한 경우 복귀 시 이전 락온을 유지하는 안을 제안한다. 연출 중 자유 이동·회피 허용은 미정.

## 8. 맵·적·아트 설계 제안

맵은 StartPoint → NarrowPath → ArenaEntrance → CircularArena → EnemySpawn 구조. 보행 속도를 v로 승인하면 길이 목표는 진입로 약 v×1초, 입구~중앙 약 v×5초로 산정한다. 중심 기준인지 몸 표면 접촉 기준인지 확인 후 실제 크기를 조정한다. 적이 움직이는 전투 중 조우 시간과 맵 배치의 보행 시간을 혼동하지 않는다.

적 FSM 후보: Dormant → Chase → Telegraph → Attack → Recovery → Chase, 추가 Hit/Dead. 공격 후보는 Sweep, Throw, LeapSlam, ChargeSlash, RetreatShot. 거리 조건 외 쿨다운·선택 우선순위·회피 이동 충돌 처리는 후속 설계에서 승인받는다. 각 공격 예고와 실제 피해 범위는 동일한 형태 데이터에서 생성하는 안을 제안한다.

로우폴리 제작안: 단순한 관절형 사람 모델·검·색상 대비로 시작하고 공통 검 부착점과 시각 루트를 둔다. 모델/리그를 게임 로직의 부모와 분리해 교체 가능하게 한다. 첫 단계는 이동·단타·막힘·분리 검증, 이후 방향별 연결과 성공/실패 각 약 5개 변형으로 확장한다. 64개 모든 자세 조합을 각각 별도 제작하는 대신 시작 자세·궤적·반응을 조합하는 구조를 제안한다. 구체적인 제작 도구, 리깅, 애니메이션 기술은 환경 확인 후 결정한다.

맵 파괴는 지정된 소품 파괴로 시작하는 안을 제안한다. 지형 자체 변형과 잔해 충돌은 범위가 달라 사전 확인한다. 특수기 3종의 내용, 기력 규칙, 회피 무적값은 아직 설계하지 않는다.

## 9. 파일 배치 제안

```text
Assets/Game/
  Scenes/             # 테스트 전투장
  Scripts/
    Player/           # 입력·이동·카메라
    Battle/           # 상태·선택·콤보·판정
    Enemy/            # FSM·패턴
    Presentation/     # 연출·시각 어댑터
    UI/               # 스탯·예약·전투 HUD
    World/            # 입구·파괴 소품
  Data/               # 승인된 스탯·패턴·밸런스
  Art/                # 직접 제작 모델·재질·애니메이션
  Prefabs/            # 캐릭터·적·전투장 요소
  Tests/              # 판정·예약 경계, 필요한 통합 테스트
md/                   # 요구사항·설계·결정·검증 기록
html/                 # 사용자 검토용 그림과 설계도
```

폴더와 클래스는 아직 생성하지 않았다. 실제 구조가 바뀌면 이 문서와 HTML을 수정한다.

## 10. 단계별 실행 및 완료 조건

| 단계 | 산출물 | 시작 전 확인 | 완료 기준 |
|---|---|---|---|
| P0 설계 | 현재 문서·설계도 | 현재 요청 | 확정/제안/미정 구분, 사용자 검토 |
| P1 기반 | 새 프로젝트·맵·로우폴리·이동·카메라 | 설치/버전/파이프라인, 이동·크기 값 | 컴파일, 이동/시점/락온, 배치 보행 시간 |
| P2 선택 | 입구·허공 베기·포커스·방향 예약 | 사거리·타이머 시작·취소/미예약 처리 | 속도별 타수/시간, 반복 제한, 선택 피해 보호 |
| P3 교환 | 평가·판정·단타/콤보·분리 | 수식/피해·검 자세·판정 시점 | 두 타 부분 예약 실행, 둘째 반복 보정, 중복 피해 없음 |
| P4 적 전투 | 추적·5개 패턴·회피·점프 | 패턴 범위/예고/우선순위·무적 | 실시간 추적/회피, 예고 범위 일치 |
| P5 확장 | 특수기·파괴·연출 변형 | 기술/파괴 범위·아트 확인 | 기술 해금, 파괴 후 진행, 다양한 교환 |
| P6 완결 | 스탯 화면·승패·재시작·템포 | 스탯 효과·게임 흐름 | 처음부터 승패까지 반복, 재시작 정상 |

스탯 데이터는 P2부터 필요하지만 스탯 배분 화면 완성은 P6에서 한다. 각 단계의 미정값은 바로 전에 구체적인 제안과 함께 질문하고, 독립적으로 진행 가능한 승인 범위는 계속 진행한다.

## 11. 검증 시나리오

| ID | 재현 | 기대 결과 |
|---|---|---|
| T01 | 원형 입구 진입 | 전투 시작, 반복 진입 중복 시작 방지 방식 확인 |
