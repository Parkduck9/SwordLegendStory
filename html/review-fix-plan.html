R1 · 동작 수정 · 우선순위 높음

메뉴를 열었을 때 모든 전투 시간이 함께 멈춰야 합니다

확인한 구현

대쉬 충전은 게임 속도와 무관한 시간으로 진행됩니다. 무적도 같은 절대 시각으로 종료되지만, 전투 관리자 안의 일부 쿨타임은 일시정지 중 멈춥니다.

플레이에서 생길 수 있는 일

대쉬 직후 메뉴를 열고 기다리면 충전은 회복되고 짧은 무적은 소진될 수 있습니다. 메뉴를 닫았을 때 시간 규칙이 서로 달라집니다.

제가 수정한다면

전투용 시간 공급원을 하나 두겠습니다. 메뉴 중에는 그 시간이 0만큼 흐르도록 하고, 충전과 무적은 그 시간을 사용합니다.

선택 제한시간은 슬로모션 중에도 실제 시간으로 세되, 메뉴 정지와 구분합니다. UI 애니메이션도 별도 시간을 사용합니다.

적 행동 가능 조건에 일시정지를 명시해 피해·충돌 처리도 막겠습니다.

검증: 일시정지 전후 충전·무적 잔여시간 비교, 정지 중 HP와 투사체 위치 유지, 기존 속도별 선택 제한시간 유지.
변경할 코드와 확인할 규칙

PlayerDash / Health / BattleFlow / EnemyBrain / EnemyProjectile 및 시간 관련 기록을 함께 확인합니다. 타이머를 한 프레임에 두 번 갱신하지 않도록 담당자를 한 곳으로 정합니다.

확인할 정책: 메뉴에서는 모든 전투 시간이 정지하도록 할지. 현재 그림은 이 정책을 제안한 것입니다.

R2 · 동작 수정 · 우선순위 높음

돌은 플레이어의 실제 몸과 겹쳤을 때 맞아야 합니다

확인한 구현

투사체와 플레이어 사이 거리를 수평면으로 계산해 높이를 제외합니다. 이동 후 위치에서만 판정하므로 빠르게 이동할 때 몸을 지나칠 위험도 있습니다.

플레이에서 생길 수 있는 일

점프로 돌 위를 넘었는데 맞거나, 프레임이 낮을 때 돌이 몸을 관통해도 피격되지 않을 수 있습니다. 실제 재현 검증이 필요합니다.

제가 수정한다면

플레이어의 CharacterController 캡슐과 돌의 반지름을 사용하겠습니다. 이전 위치에서 새 위치까지 이동한 구간 전체를 검사합니다.

벽과 몸이 모두 경로에 있으면 먼저 만난 대상을 처리합니다. 기존 피해 진입점을 사용해 무적·패링 규칙도 유지합니다.

점프 자체에 무적을 주는 제안이 아닙니다. 돌과 몸이 겹치면 점프 중에도 맞습니다.

검증: 지상에서 1회 피격, 점프 아래로 지나가면 회피, 몸 높이에서는 피격, 낮은 프레임에서도 판정, 벽이 먼저면 벽에서 종료.
변경할 코드와 확인할 규칙

EnemyProjectile의 수평 거리 판정을 이동 구간 검사로 교체합니다. 시작점 겹침도 처리하고 EnemyBrain.ReportHit → Health 흐름을 유지합니다.

확인할 기준: 몸체와 겹쳐야 피격되는 방식. 캡슐 크기와 돌 반지름은 플레이를 보며 조정해야 합니다.

R3 · 인계 문서 수정 · 우선순위 높음

현재 상태와 과거 기록을 분리하면 인계가 쉬워집니다

구현 현황 문서 위쪽에는 “적이 아직 정지 상태” 같은 오래된 내용과 이전 다음 작업이 남아 있습니다. 아래쪽 기록에는 이미 적 AI와 후속 구현이 진행되어 있습니다.

제가 수정한다면

최신 코드와 로드맵을 대조해 문서 맨 위에 현황 요약을 다시 씁니다. 오래된 기록은 날짜를 붙여 이력으로 옮기고, 이미 완료된 다음 작업과 없어진 클래스 이름을 정리합니다.

완료 표시도 구분

코드 작성 / 컴파일 확인 / 규칙 검증 / 실제 Play 확인 / 사용자 체감 확인을 나눕니다. 빌드가 통과했다고 재미나 연출까지 확인된 것으로 표시하지 않습니다.

검증: 문서 상단과 로드맵·코드의 상태 일치, 파일 경로 확인, 과거 기록 보존. 진행 중인 사운드 등 최신 작업도 다시 읽고 반영합니다.
R4 · UI 개선 · 배치 확인 필요

공격을 고르면서 검의 시작 위치도 볼 수 있어야 합니다

현재 선택 휠은 화면 중앙 근처에 크게 배치되어 있습니다. 사용자가 원하는 “플레이어와 검에 카메라 포커싱”이 잘 보이려면 인물과 선택 UI가 서로 가리는 면적을 줄여야 합니다.

제가 수정한다면

우측 휠 배치부터 간단한 시안으로 확인받고 적용하겠습니다. 검과 플레이어는 중앙 왼쪽에 보이게 하고, 공격 예약과 제한시간을 휠 가까이에 모읍니다.

다른 선택지도 가능

중앙 휠을 유지하면서 크기와 불투명도를 낮추는 방법도 있습니다. 우측 이동 시에는 마우스 방향 입력과 UI 중심이 어긋나지 않게 함께 검토해야 합니다.

검증: 1920×1080·1280×720·16:10에서 검과 글자 확인, 8방향 선택 정확도, 같은 방향 두 번과 특수기 세 번 입력, 타이머 가독성.
변경할 코드와 사용자 확인

SelectionWheelView 배치와 입력 표시를 조정합니다. 고정 픽셀값만 옮기지 않고 화면 크기에 맞춰 배치합니다.

확인할 내용: 우측 휠과 중앙 축소 휠 중 선호하는 배치. 정확한 크기·투명도는 아직 정하지 않았습니다.

R5 · 핵심 기능 확장 · 규칙 확정 후 구현

검 자세와 적 스탯이 실제 성공률에 연결되어야 합니다

현재 연결된 것

성공률 계산에는 플레이어 스탯, 정면·후면, 반복 공격, 공중 공격 등의 조건이 들어갑니다. 검 자세는 연출과 선택 안내에 사용됩니다.

아직 부족한 것

플레이어 검의 시작 위치·선택 방향·적 검 위치·적 스탯을 함께 비교하는 성공률 계산이 없습니다. 처음 요청한 전술을 완성하기 위한 추가 작업입니다.

제가 수정한다면

공격 선택 시 두 캐릭터의 스탯·위치·시선·검 자세를 하나의 전투 스냅샷으로 모읍니다. 공통 계산기가 성공률과 피해량을 평가하게 하겠습니다.

화면에 표시하는 성공률과 실행 때 사용하는 성공률은 같은 계산을 사용합니다. 각 타격 결과의 확률 추첨은 연출 전에 처리하며 추첨 화면은 보여주지 않습니다.

먼저 함께 정해야 할 규칙

  • 8방향 기준: 화면 방향, 플레이어 몸 방향, 적을 기준으로 한 방향 중 무엇인지.
  • 검 자세 상성: 어떤 조합이 유리·중립·불리인지. 적 스탯은 어떤 항목과 값을 갖는지.
  • 연속타 계산: 1타 성공·방어 뒤 바뀐 검 자세를 2·3타 확률에 어떻게 반영할지.
  • 방어와 패링: 하나의 실패 결과로 묶을지, 별도 확률과 효과로 나눌지.

아직 정하지 않은 확률 수치와 상성표를 임의로 넣지 않겠습니다. 기존 반복 공격·치명타·특수기 보장 규칙과 충돌하지 않는지 먼저 확인합니다.

검증: 동일한 정보에서 표시 확률과 실행 확률 일치, 검 자세·적 스탯 변화 반영, 고정 난수로 결과 재현, 반복타와 보장 특수기 유지.
변경할 코드와 설계 선택

StrikeContext / StatEffects / CombatResolver와 검 자세 데이터의 연결을 확장합니다. 예시 이름인 CombatSnapshot / CombatEvaluator는 아직 추가된 클래스가 아닙니다.

예약 때 확률을 고정할지, 앞선 타격 결과에 따라 다음 타격을 다시 계산할지 결정해야 합니다. 재계산을 택한다면 미리 보여주는 확률의 의미도 설명해야 합니다.

해결법과 순위

코드를 다시 읽어 R1~R5를 모두 사실로 확인했습니다. R2는 투사체 높이가 1.3m라 지금은 체감이 작지만, 빠르게 날아갈 때 몸을 통과할 위험은 실제로 있습니다. R5는 버그가 아니라 게임 규칙을 정해야 하는 확장입니다. 굵은 줄(1순위)로 적용했습니다.

순위해결법장점단점한줄평
